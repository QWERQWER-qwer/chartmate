# B 담당 — 프론트엔드 / QA / README

## B-1. 프론트엔드 개선
로컬 실행: `frontend/index.html`을 브라우저로 열면 됨(정적 파일). 백엔드는 배포본(onrender)을 자동으로 바라봄.

- [ ] **관심종목 저장 UI** — 사용자가 자주 보는 종목을 저장/불러오기 (간단히 브라우저 localStorage로 시작 가능)
- [ ] **모바일 반응형 점검** — 휴대폰 화면에서 입력창·칩·브리핑 카드가 안 깨지는지 확인·수정
- [ ] **디자인 다듬기** — 여백·폰트·색 등 가독성 개선
- [ ] 작업분을 `frontend/`에 커밋
- 완료 기준: 모바일에서도 깨짐 없이 동작 + 개선 커밋 존재

## B-2. QA 테스트 (버그 찾기)
아래를 실제로 넣어보고 이상하면 **GitHub Issues에 등록**(제목+재현방법+스샷):

- [ ] 여러 종목: 해외(AAPL·TSLA), 크립토(비트코인), 한국 종목
- [ ] 사전에 없는 종목명 입력 시 어떻게 되는지
- [ ] **차트가 아닌 이미지**(사진·밈 등) 업로드 시 "차트 아님" 응답 나오는지
- [ ] 분봉/주봉 차트 업로드 시 해석 양상
- [ ] 후속 질문("그럼 애플은?", "이 차트 지지선 다시")
- 완료 기준: 발견한 이슈가 Issues에 등록됨

## B-3. README 최종화  ← B가 총괄
저장소 루트 `README.md`는 이미 뼈대가 있음. 아래를 채워 완성:

- [ ] **팀원 및 역할 표** — 실제 이름 + 각자 한 작업 1~2문장
- [ ] **배포 URL** (Vercel 주소), **백엔드 URL** 기입
- [ ] **기술 스택 / 실행 방법** 최신 상태 확인
- [ ] **사용자 테스트 결과** 섹션 — ★C가 정리해 준 내용을 받아서 기입
- [ ] **협업 과정** 섹션 — 커뮤니케이션 방식·미팅·역할 수행 요약
- 완료 기준: README만 보고 프로젝트 개요·실행·결과를 알 수 있음

# C 담당 — 사용자 테스트 / 피드백 / 문서  (핵심)

## C-1. 구글폼 제작
- [ ] 구글폼 새로 만들기 → 아래 3문항 입력
  1. 차트 해석·지표 설명이 종목 이해에 도움이 됐나요? (1~5점, 선형배율)
  2. 가장 유용했던 기능 / 불편했던 점은? (장문형)
  3. 다시 쓸 의향이 있나요? 개선 제안이 있다면? (장문형)
- [ ] 폼 링크 발급 → `docs/user-test/폼링크.md`에 기록·커밋

## C-2. 실사용자 5명+ 테스트 운영 (필수 요건)

- [ ] 배포 URL + 구글폼 링크 전달
- [ ] 응답 5개 이상 수집

## C-3. 피드백 정리

- [ ] 개선 항목을 B/민재에게 전달 → 다음 개선에 반영

## C-5. README용 결과 전달
