# ChartMate 기획서 (가칭)

- **프로젝트명**: ChartMate
- **한 줄 소개**: 차트 해석과 지표 조회를 대화 한 번으로 대신 해주는, 투자 초보용 AI 투자 비서
- **작성일**: 2026-11-03
- **팀**: 3인 (팀원 섭외 후 확정 — 9번 참조)

---

## 1. 문제 정의

개인 투자자, 특히 **투자 초보**가 실제로 겪는 두 가지 불편에서 출발한다.

1. **차트를 봐도 해석을 못 한다.** 캔들·추세·패턴이 무슨 의미인지 몰라 "올랐다/내렸다" 이상으로 읽지 못한다.
2. **종목마다 지표를 매번 찾아보기 번거롭다.** 현재가·이동평균·RSI 등을 보려면 여러 사이트·앱을 오가야 하고, 보는 종목이 늘수록 이 반복이 부담이 된다.

문제의 본질은 '정보가 없어서'가 아니라 **정보가 흩어져 있고 해석이 안 돼서** 생긴다. 그래서 초보는 투자 의사결정의 전 단계인 '현황 파악'조차 진입장벽으로 느끼고, 매번 검색·해석에 시간을 쓴다. 이 두 불편을 **대화 한 번으로 줄이는 것**이 이 서비스의 목적이다.

## 2. 타겟 사용자 & 해결 아이디어

**타겟**: 본인과 같은 개인 투자자, 그중에서도 투자 초보.

**왜 이들인가 (기준 → 대입)**
- 기준: (가) 지표 해석 능력이 낮다, (나) HTS·유료 단말에 익숙하지 않다, (다) 가벼운 도구를 원한다.
- 대입: 초보는 1번의 두 불편(해석·조회)에 모두 막히므로, 이 서비스의 효용이 가장 크게 나타나는 집단이다.

**해결 아이디어**: 종목에 대해 "지금 어때?"라고 물으면 비서가 ① 실시간 시세·지표를 직접 조회해 요약하고, ② 사용자가 올린 차트 이미지를 해석해주고, ③ 내 관심종목·과거 대화 맥락을 기억해 이어서 답하는 **대화형 투자 비서**.

## 3. AI 활용 방식 (기준 → 대입)

**기준**: 1번에서 정의한 불편 각각에 대응하는 AI 기능을 붙이고, 과제 필수 기술요소(2개 이상)를 충족한다.

**대입**

| 불편 | 대응 AI 기능 | 필수 기술요소 |
|------|-------------|--------------|
| ① 차트 해석 못 함 | 차트 이미지를 올리면 비전 모델이 추세·주요 구간을 읽어 자연어로 해설 | **멀티모달** |
| ② 지표 조회 번거로움 | "엔비디아 지금 어때?"에 비서가 스스로 시세·지표 조회 툴을 호출 (사용자가 사이트를 돌 필요 없음) | **AI Agent (function calling)** |
| 공통 (맥락 유지) | 관심종목·대화 기록을 사용자별 저장, 다음 대화에서 자동 로드 | **Long-term Memory** |

→ 필수 기술요소 **3개** 충족 (요건은 2개, 여유 있게 초과).

**프롬프트 설계 원칙**: 매수·매도 '지시'나 '권유'를 하지 않고 '현황 설명·지표 해석'에만 한정한다 (윤리·법적 한계 — 7번 참조).

## 4. 기술 스택 선정 이유

정직하게 밝힌다: 핵심 스택은 이번에 새로 고른 것이 아니라, **선행 프로젝트('데이터 AI 비서')에서 구축·배포·검증한 것을 재사용**한다.

**왜 재사용인가**: Final Project의 목표는 짧은 기간 안에 '배포 → 실사용자 검증'까지 완주하는 것이다. 바닥부터 다시 세우는 대신 **검증된 기반 위에 신규 기능(Agent·멀티모달)만 얹는 것**이 기간 제약 하에서 최선이다.

| 구분 | 선택 | 이유 |
|------|------|------|
| 백엔드 | FastAPI (Render 배포) | 기존 결정. async·자동 문서화(/docs)가 Agent 툴 호출·테스트에 유리 |
| 프론트 | 바닐라 HTML/CSS/JS (Vercel) | 기존 결정. 프레임워크 학습비용 없이 빠르게 |
| DB | Firebase Firestore | 기존 결정. 관심종목·대화기록 저장(LTM)에 사용 |
| 생성형 AI (대화) | OpenAI API | 선행 '데이터 AI 비서'에서 결정·검증. 대화 비서의 기반 |
| 멀티모달 (차트 해석) | Google Gemini 비전 (`gemini-3.5-flash`) | 기존 텔레그램 봇의 차트 이미지 분석 코드를 그대로 이식 |
| 신규 | yfinance | Agent 툴의 시세·지표 조회용으로 추가 |

**멀티모달 모델 선택 (왜 Gemini인가)**: 대안은 OpenAI 비전으로 스택을 하나로 통일하는 것이었다. 그러나 기존 텔레그램 봇에 이미 **Gemini 비전 기반 차트 이미지 분석 코드가 검증된 상태로 존재**하므로, 이를 재사용하는 편이 기간 제약 하에서 더 빠르고 안전하다. 그래서 스택은 이원화(대화=OpenAI, 비전=Gemini)하되, 각 코드 자산을 최대한 재활용하는 쪽을 택했다.

## 5. 시스템 아키텍처 (개요)

```
사용자(브라우저)
  → Vercel 프론트 (채팅 UI + 차트 이미지 업로드)
  → FastAPI (Render)
       ├─ OpenAI API       : 대화 응답 (AI 비서 본체)
       ├─ Gemini 비전       : 차트 이미지 해석 (멀티모달)
       ├─ 시세/지표 조회 툴  : yfinance (Agent function calling)
       └─ Firestore        : 관심종목·대화기록 (Long-term Memory)
```
(상세 다이어그램은 기능요구명세서에 첨부)

## 6. 구체 스펙 (재현 가능하게) — 일부는 제안값, 확정 필요

- **Agent 툴**: `get_price(ticker)` 현재가·등락률, `get_indicators(ticker)` 아래 지표 묶음.
  - **지표 세트 (선정 근거: 본인이 과거 트레이딩 봇 작업에서 실제로 쓰고 유효성을 검증한 것 중심)**
    - **이동평균선 (60일·200일선)** — 과거 작업에서 '이동평균선(nnn일선)'이 실제로 쓸만했던 두 접근 중 하나였고, 핵심 전략에 200일선 필터를 사용했다.
    - **모멘텀 (예: 126일)** — 나머지 하나의 쓸만했던 접근. 핵심 전략이 126일 모멘텀 기반이었다.
    - **ATR (변동성)** — 기존 텔레그램 봇에서 ATR 기반 '안전 매수가' 산정에 사용했다.
  - 초보 타겟에 맞춰, 수치만 던지지 않고 "지금 추세선 위/아래, 변동성 높음/낮음"처럼 **해석을 붙여** 전달한다.
  - (RSI·볼린저밴드는 핵심 지표에서 제외 — 과거 작업에서 주력으로 삼지 않았다.)
- **차트 해석**: 입력 이미지 1장(PNG/JPG, 용량 상한 설정), 출력은 추세·주요 지지/저항 '관찰' 설명 (예측 아님).
- **Long-term Memory**: 사용자별 관심종목 목록 + 최근 대화 요약을 시스템 프롬프트에 주입.
- **응답 목표**: 일반 질의 5초 이내 (선행 프로젝트 NFR 재사용).

> 이동평균/모멘텀의 세부 기간(60·200·126일)과 이미지 용량 상한은 구현 단계에서 조정 가능한 값이다. 지표 '선정'의 근거는 위와 같이 본인의 실제 경험이다.

## 7. 예외와 한계 (구현/미구현 명시)

**예외 처리 (구현 예정)**
- 시세 데이터 미수신(티커 오류·API 실패) → "조회 실패" 안내 + 재시도 유도.
- 차트가 아니거나 판독 불가한 이미지 → "해석 불가" 응답.

**한계 (정직하게)**
- 비공식 시세 API(yfinance) 사용 → 실시간성·정확성 보장 안 됨, 지연 가능 (보완 **미구현**).
- 차트 해석은 비전 모델의 '관찰'이지 미래 예측이 아님. 정확도 보장 불가.
- 본 서비스는 **투자 참고용이며 투자자문·매매 권유가 아니다.** AI 생성 콘텐츠임을 UI에 명시 (윤리 요건).
- 개인정보는 수집 시 동의를 받고 안전하게 저장하며, 민감정보는 수집하지 않는다.
